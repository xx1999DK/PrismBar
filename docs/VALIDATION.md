- Intel Mac，macOS 15.7.9（24G830），Swift 6.1.2。
- `bash scripts/test.sh`：21 项行为检查通过，包括延迟、菜单打开及鼠标停留时的收回保护、中英文/全半角搜索、收藏筛选、坏偏好恢复及屏幕坐标边界。
- `--smoke-test`：状态项创建、分隔项宽度折叠/展开、十种主题符号、设置窗口、抽屉重复激活不被设置窗口替换、正常退出通过。这验证本程序状态，不代表外部图标的视觉排布已经验收。
- 已安装并启动 `/Applications/PrismBar.app`。最终构建诊断为 `accessibility=granted`，独立诊断读到 17 个状态项；抽屉实际显示 16 个外部项目（诊断进程可额外读到正在运行的 PrismBar）。
- 实际 UI 验证：显示外部菜单项目、输入 `codexvolt` 筛选、右键加入常用、常用筛选、移除测试收藏。保留用户已有主题、收藏和登录项设置。
- 从抽屉打开了系统原生 Wi-Fi 浮层，未切换网络或修改网络设置。该项测试发生在最终菜单超时修复之前，修复后尚未完成交互复测。
- 最终 x86_64 与 arm64 ZIP 均通过压缩包完整性、元数据、SHA-256 和本地 ad-hoc 签名验证；安装的 Intel 可执行文件与最终 ZIP 内逐字节一致。ARM 为交叉编译，未真机运行。每个 ZIP 约 1.7 MB。
- 最终程序导出 23 张原生视图预览（3 页设置、10 主题的深浅色抽屉）。十主题联系表此前已目视检查，本次概览新按钮预览已重新检查；演示项目不来自用户账户或真实机器内容。
- 源码及文档检查未发现令牌、私钥、个人机器路径或实际扫描得到的账户标识。发布素材只用原生演示预览。

## 本轮发现与修复

- ad-hoc 构建替换后，系统可显示开关开启，但 API 仍未授权。移除旧条目、添加当前应用并重新检测后恢复。没有绕过 TCC 或修改全局安全设置。
- 重复激活 App 会把已打开的抽屉替换为设置窗口。现已保留可见抽屉、增加概览直接入口，并加入原生回归检查。
- CodexVolt 原菜单点击曾被误判失败。Apple 的 `AXUIElementPerformAction` 文档说明模态回调可能超时，但动作未必失败。现保留真实错误码；超时不重复点击，不用错误抽屉抢走菜单焦点；能确认目标菜单时继续保护，不能确认时保持展开并暂停收回。该修复的最终视觉效果待用户观察确认。
- 控制中心使用系统对话框而不是普通 AXMenu，已补充浮层角色检测。只检查焦点和角色属性，不读取窗口文档内容。各 AX 对象读取均设置超时，避免误以为父节点超时会传递给子节点。
